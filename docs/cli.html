The evault command

It ships inside eVault.app and reads the same vault as the app. While eVault is running, it gets the key from the app after you approve with Touch ID, so you never type the passphrase into a shell.

On this page

Install

In eVault, open Settings › Command Line › Install evault Command and pick a folder on your PATH (Homebrew’s bin works). It adds a link into the app, so app updates update the command. Or in Terminal:

$ sudo ln -sf /Applications/eVault.app/Contents/Helpers/evault /usr/local/bin/evault $ evault status

Unlocking

A command that needs the key tries, in order:

  1. the key cached by evault unlock
  2. $EVAULT_PASSPHRASE, if set
  3. the running eVault app: it shows a Touch ID prompt and hands over the key for that one command (it starts the app in the background if needed)
  4. a passphrase prompt
evault statusIs the app running, which vault is open, locked or not.
evault unlock [--passphrase]Cache the key in your login keychain, for shell hooks. Uses Touch ID through the app unless you pass --passphrase.
evault lockForget the cached key.

Everyday

evault lsList projects and their items.
evault get <project> <item>Print an item’s contents.
evault run <project> <item> -- CMDRun a command with the file’s variables set. Nothing is written to disk.
evault pull <project> <item> [-o PATH]Write the env file to disk, readable only by you.
evault push <project> <item> <FILE>Create or update an item from a file; creates the project if needed.
evault history <project> <item>List revisions, with the Mac that made each.
evault example <project> <item>Print a .env.example: same keys and comments, secrets blanked.

Shell integration Pro

Link a folder to an env file; the hook exports its variables when you cd in and unsets them when you leave. Run evault unlock once so the hook never has to ask.

# ~/.zshrc (bash: ~/.bashrc · fish: evault hook fish | source) eval "$(evault hook zsh)" $ cd ~/code/shop && evault link shop .env.local
evault link <project> <item> [DIR]Bind a folder (default: the current one) to an env file.
evault unlink [DIR] · evault linksRemove a binding, or list them.
evault env [--fish]Print export lines for the file linked to this folder.

Import

Bring secrets in from wherever they live now. An item with the same name is updated, not duplicated.

evault import <project> <item> <FILE|->A .env file, JSON (flat, Doppler or a 1Password item) or a .env.vault, decrypted with $DOTENV_KEY. - reads stdin.
… --doppler [-- doppler args]From doppler secrets download, e.g. -- --project shop --config prd.
… --1password <item> [-- op args]From op item get; each field becomes a variable.

GitHub Actions secrets can’t be imported: GitHub never returns their values.

Keeping secrets out of git

The pre-commit hook scans what you are about to commit for AWS, GitHub, Stripe, Slack, OpenAI and Google keys, private key blocks, JWTs, secret-looking assignments and real .env files. Add evault:allow to a line that is a false positive; git commit --no-verify skips the check once.

evault protect [DIR] [--remove]Install or remove the hook. Keeps any hook you already have and honours core.hooksPath.
evault scan --stagedWhat the hook runs: scan the staged files.
evault scan [DIR]Scan a whole source tree, skipping node_modules, build folders and binaries.

Deploy

Uses the vendors’ own CLIs and the logins you already have. --dry-run prints what would run.

evault deploy vercel <project> <item>--target production|preview|development
evault deploy cloudflare <project> <item>Worker secrets via wrangler secret bulk; pass wrangler options after --.
evault deploy github <project> <item>Actions secrets via gh secret set; --repo owner/name.

Options and variables

--vault DIR · $EVAULT_DIRWhich vault. Default: the one open in the app, else the eVault folder in iCloud Drive.
$EVAULT_PASSPHRASEPassphrase for scripts and CI.
EVAULT_NO_APP=1Never ask the eVault app; use the cache or the passphrase.
$DOTENV_KEYDecrypts a .env.vault on import.
