## Decisions in force

- Free: 3 projects, folder sync, editor, history, Touch ID, CLI, AI agent support (MCP). Pro $29 one-time: unlimited projects, CloudKit sync, menu bar quick copy, developer tools, shell integration, 12 months of updates. Team: in progress (below).
- **Team plan** (decided 2026-10-19; plan + SRS: [EnVault Team Features — Plan & SRS](https://claude.ai/code/artifact/4eaf2c20-2ccf-4c13-abf6-f231b4143b79)): annual per-seat subscription, prices in the plan doc, no seat cap (performance is tested at 100 members). Members join a team vault on Free; the owner holds the Team license. Team 1.0 supports both CloudKit sharing and shared-folder (Dropbox, git) teams. Crypto review of the key and signing design (NFR-16): Claude Code Reviews.
- Sync v1 = encrypted folder in iCloud Drive; CloudKit mirror is the Pro backend.
- Licenses: offline Ed25519 keys (`EVL1.payload.sig`), no activation server, no analytics, no network entitlement in the app.
- **Payments: Polar** (merchant of record; seller in Vietnam; Polar lists Vietnam as a payout country, pays VND to a local bank). **Paddle is the fallback** (USD payouts, Payoneer or USD account). Lemon Squeezy rejected.
- Refunds: 14 days. A full refund revokes the key in the store; the id ships in the next app release.

## Vendor secrets (never in the repo)

| Secret | Location |
|---|---|
| License signing key (Ed25519 private) | login keychain `dk.dinhkhanh.evault.license-signing`; backup in password manager; also becomes the Worker secret `LICENSE_PRIVATE_KEY` |
| License public key | `Packages/EnVaultKit/Sources/LicenseKit/VendorKey.swift` (the app's `LicensePublicKey` and the CLI read it), `store/wrangler.toml` (`LICENSE_PUBLIC_KEY`) |
| Sparkle EdDSA key | login keychain; on the release Mac the current `SRLH…` key is account `ed25519-srlh` (account `ed25519` there holds the retired `sEM9…` key); the release scripts sign with `ed25519-srlh` unless `SPARKLE_ACCOUNT` says otherwise; backup in password manager; public key in `project.yml` (`SUPublicEDKey`) |
| Store admin token | Worker secret `ADMIN_TOKEN`; keychain `dk.dinhkhanh.evault.store-admin` |
| Polar / Paddle / Resend secrets | Worker secrets only (Resend key "envault-store (Cloudflare Worker)", sending-only, scoped to `envault.app`) |
| Apple team id | git-ignored `Config/Signing.xcconfig` |
| Offline license ledger | `~/Library/Application Support/EnVault Vendor/licenses.jsonl` (fallback only; D1 is the ledger of record) |

Back up both keychain keys. Losing the license key means no new keys can be issued; losing the Sparkle key means existing installs cannot update.
Rotations so far, all before any sale: 0.3.2 rotated both pairs on another machine (`Oh6B…`/`sEM9…`) because the originals looked missing there; those private halves never reached this Mac, so 0.3.6 (2026-10-15) rotated both again here. Keys are per machine: before releasing or issuing, check the keychain's public key against the repo (`generate_keys -p` vs `SUPublicEDKey`; the license seed vs `VendorKey.swift`). Retired keys kept in the keychain: license `dk.dinhkhanh.evault.license-signing.old-2026-10-14`, Sparkle account `ed25519-old-2026-10-14` (both the pre-0.3.2 pairs).

Restore on a new Mac or after a keychain reset:
- License key: `security add-generic-password -s dk.dinhkhanh.evault.license-signing -a envault -w '<key>'`
- Sparkle key: save it to a file, then `build/SourcePackages/artifacts/sparkle/Sparkle/bin/generate_keys -f <file>` (export with `-x <file>`)

## Routine operations

- Release: bump `MARKETING_VERSION`, `CURRENT_PROJECT_VERSION`, `ENVAULT_RELEASE_DATE` (quoted) in `project.yml`; `make archive` (signed, notarized; `make release-unsigned` only as a fallback); tag `vX.Y.Z`; `gh release create` with dmg, zip, `EnVault.dmg` (unversioned copy the site's Download buttons link to via `releases/latest/download/EnVault.dmg`), SHA256SUMS, appcast.xml. The release scripts pull revoked ids from the store first.
- Customers: `scripts/store.sh list [query]`, `issue --email E --name N`, `revoke --email E --reason R`, `resend --email E`. Self-service: `/resend` on the store.
- Tests: `make test` (Swift), `make store-test` (Worker).
