Three ways to reach a secret

In the app

Projects, env files, secrets and notes. An editor with history, line numbers and warnings, and a key-by-key comparison with your other environments.

Over any app, with ⌥⌘E

A search panel above whatever you are doing. Type part of a key, press Return, paste. The clipboard clears itself and clipboard managers skip it.

In Terminal

The evault command ships inside the app. It asks eVault for the key and you approve with Touch ID, so you never type the passphrase into a shell.

Everything a .env file should have had.

New in 0.4: quick copy over any app, Touch ID for the command line, importing whole project folders, files kept in sync on disk, and a commit hook that stops leaks.

New Pro

Quick copy over any app

Press ⌥⌘E anywhere. Search keys, secrets, notes and values, with the ones you copy most at the top. Return copies the value, ⌥Return an export line, ⌘Return KEY=value.

New

Touch ID for the command line

When eVault is running, evault asks the app for the key and you approve with Touch ID. Install it from Settings in one click; app updates update it too.

New

Import your whole projects folder

Point eVault at ~/Projects. Each folder becomes a project with its .env files; templates like .env.example are skipped. Also imports Doppler, 1Password items, JSON and .env.vault.

New Pro

.env kept in sync in the project

Link an item to a project folder and eVault rewrites the file whenever it changes, here, on another Mac or from the CLI. Edits you made on disk are never overwritten without asking.

New

Secrets stay out of git

evault protect adds a pre-commit hook that stops commits containing API keys, tokens, private keys or a real .env file. Mark a false positive with evault:allow.

New

An editor that catches mistakes

Line numbers and warnings for duplicate keys, empty or placeholder values and broken lines. See which keys .env.production has that .env.local lacks, and add them in one step.

Every change kept

Each edit is a new revision you can diff and restore, with the Mac that made it. Keys whose value hasn’t changed in 90 days are flagged for rotation.

Pro

Variables load when you cd

Link a folder to an env file and the shell hook (zsh, bash or fish) exports its variables when you enter and unsets them when you leave.

Deploy without copy-paste

Push an env file to Vercel, Cloudflare Workers or GitHub Actions secrets with evault deploy, using the vendor CLIs and logins you already have.

Plus, in Pro: env diff, .env.example generator, secret scan, JWT decoder, UUID and password generators.

Zero-knowledge by construction

We can’t read your vault. Neither can iCloud.

Encrypted before it’s written

Every revision is its own AES-256-GCM file. The key comes from your passphrase on your Mac (PBKDF2, 600,000 rounds). Sync only ever carries ciphertext.

No conflict copies

Files are never overwritten, so iCloud Drive, Dropbox or git can’t produce conflicts, and offline edits on two Macs merge cleanly.

No network access

The app is sandboxed without a network entitlement. macOS does the syncing; eVault has no servers and no analytics.

Touch ID, auto-lock, clean clipboard

Unlock with Touch ID, lock on sleep or after idle time. Copied values are hidden from clipboard managers and cleared after 30 seconds.

Every CLI unlock approved

The command line gets the key only after you approve it in a system Touch ID prompt, one command at a time. You can turn this off in Settings.

Recovery key, open format

A one-time recovery key gets you back in if you forget the passphrase. The vault format and crypto are open source: read the threat model.

Built for the terminal too.

Run a command with an environment injected, pull a file, import from Doppler or 1Password, deploy to Vercel. The same vault, the same Touch ID.

A vault is a folder.

vault.json holds your key-derivation settings and the vault key, wrapped by your passphrase. Every change writes a new .evr file that is never touched again. Choose how it travels:

Folder · Free

Keep the vault in iCloud Drive, Dropbox, Syncthing or a git repo. No account, nothing to set up.

iCloud · Pro

The vault lives in the app and mirrors to your private CloudKit database. Your other Macs on the same Apple Account open it with the passphrase.
